# Shiftly

Shiftly runs as a GitHub Pages PWA with Supabase Auth, Postgres and Edge Functions. The source includes the roster engine, private notes, sharing, offline queues, audit history, ICS feeds and two-way CalDAV integration.

## Develop and build

Use Node 24 and the pnpm version in package.json. Run `pnpm install --frozen-lockfile`, `pnpm dev`, `pnpm test`, `pnpm typecheck` and `pnpm build`.

`standalone/config.json` contains public browser configuration only. Never put a service-role key or private credential there. Build output, dependencies and environment files are ignored.

## Deploy

Pushes to main build and publish `standalone-dist` through GitHub Actions. Enable GitHub Pages with GitHub Actions as the source. The public URL is https://wiggli.github.io/Shiftly/.

The backend entry is `standalone/server/index.ts`. `pnpm build:backend` bundles it to `supabase/functions/shiftly-api/index.js`. Deploy that bundle as the `shiftly-api` Edge Function, with platform JWT verification disabled because the function verifies Google sessions itself and CalDAV uses account-specific credentials. The service-role key stays in Supabase's server environment. Apply `supabase/schema.sql` once to initialize the private schema. Do not reapply it over production data without review.

Allow https://wiggli.github.io/Shiftly/ as an authentication redirect in Supabase. The Google provider must be configured. CalDAV server addresses are generated by the backend and include its full function path.
